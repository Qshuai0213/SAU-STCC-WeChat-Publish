# 设计实践笔记（可选参考）

> 2026 年纳新推文实战沉淀的设计经验，属于**可选的进阶手法**：不用不影响合格产出，用得当更耐看。
> 所有手法均经 headless Chrome（Blink 内核，与微信 X5/WKWebView 同族）渲染验证。

## 一、微信安全手法清单（硬约束）

- 禁用 `box-shadow`（编辑器渲染不稳定）
- 禁用 `position:absolute`（X5 内核易错位）
- 禁止给文字压渐变背景（darkmode 下会触发 darkmode-no-gradient 类问题；渐变字除外，见下）
- RGBA/PNG 转 RGB 时**必须先铺白底再丢 alpha**，否则透明区会变成黑底
- 可用：`transform:rotate/skew`、负 margin 叠压、`background-clip:text` 渐变字（X5/WKWebView 均支持）、inline span 上的 `linear-gradient` 荧光笔

## 二、层级编号用字体形态，不用色块

"章节标题"与"条目标题"都写成"数字 + 标题"时两级会撞车。改用衬线数字（Georgia）的三种形态分层：

- 章：38px 渐变斜体实心（`background-clip:text`）+ 菱形节点
- 节：20px 淡蓝幽灵（无菱形）
- 数据：30px 实心 + 上下细规则线

区分靠字号与虚实，不靠颜色深浅和底色块。

## 三、荧光笔划重点

文字底部 38% 上淡蓝的"记号笔"效果，比色块卡片轻、比纯加粗醒目：

```html
<span style="background-image:linear-gradient(180deg, rgba(23,90,223,0) 62%,
  rgba(23,90,223,0.16) 62%);">关键句</span>
```

全篇建议不超过 3 处，只用在最核心的定位句和数据句上。

## 四、照片零包装

照片直接放置 + 灰色图注。相框、底板、左竖条、错位块都是画蛇添足——照片本身是版面最强的视觉元素，任何包装都会喧宾夺主。

## 五、装饰母题要少且贯穿

全篇装饰母题不超过两个（如：菱形节点 + 短下划线条），反复出现但形态克制。每处换一种装饰 = 没有设计。

## 六、避免清单（已验证不耐看）

- **错位色块垫底**：单处点缀可以，全篇复用必然同质化
- **正文套色块卡片**：AI 感的主要来源，正文保持纯段落
- **照片加相框/底板/竖条**：画蛇添足
- **菱形/箭头类无功能分隔线**：删除，靠留白与标题分量分段

## 七、排版类任务的校验流程（通用）

1. 逐字比对：所有源文本以 find-in-file 方式验证在位且顺序一致
2. 图片计数与 base64 解码校验
3. headless Chrome 整页渲染 + 分片目检 + 关键位置像素采样（黑底、透明失效靠像素采样发现）
4. 结构校验：`<section>` 开闭配对计数

## 八、已知限制

- 微信文章列表接口（`profile_ext`）在浏览器端返回"请在微信客户端打开"，**无法枚举公众号历史文章**；单篇文章可经 Tavily 代理读取（直接抓取会被"环境异常"验证拦截）
- 渐变字（`background-clip:text`）在极旧机型上若失效，文字会随 `color:transparent` 隐形——重要位置建议准备纯色保底方案
